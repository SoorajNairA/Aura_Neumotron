# New-project Firmware, Simulation, Views and Breadboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any project built through "Design with AURA" gets consistent firmware (drivers + validated rule list), a rule-driven fault simulation, exact pin/wire labels with highlighting, a breadboard when appropriate, and detailed 3D models.

**Architecture:** One IO model derived from the Engineering Graph (`firmware/io.py`) feeds the rule validator, the C++ sketch generator (`firmware/generic.py`) and, via the firmware API, the TS rule evaluator (`rules.ts`). Rules come from Nemotron as JSON at proposal time and are stored per project like firmware edits. Pin allocation moves into one shared function used by the planner and library adds.

**Tech Stack:** FastAPI, Engineering Graph, pytest; React 18 + TS + Three.js, vitest, Playwright; arduino-cli (ESP32 core).

**Spec:** `docs/superpowers/specs/2026-10-28-new-project-firmware-simulation-views-design.md`

## Global Constraints

- Nemotron never writes C++; it returns the rule-list JSON only. Rules are validated deterministically.
- Pins come only from the controller `gpio_map`. ADC1 pins for analog inputs: `(32, 33, 34, 35, 36, 39)`. Input-only `(34, 35, 36, 39)` never for outputs. Strapping `(0, 2, 5, 12, 15)` never auto-assigned.
- Libraries: `OneWire@2.3.8`, `DallasTemperature@4.0.5`, `ESP32Servo@3.2.1`.
- Exact copy: `Behavioral model — same rule as firmware, not running on hardware`; `Default rule — not generated by the live model`; `No driver yet`; `uncalibrated`; `Generic proxy`; `nominal standard size`; `Firmware does not compile`.
- Fan demo unchanged: `generate_fan_sketch`, `fanControl`, fan simulation and their tests keep passing.
- No new Python/npm dependencies.
- GitNexus impact before editing existing symbols (warn HIGH/CRITICAL; UNKNOWN = unresolved); detect-changes before every commit.
- Python tests: `export PATH="/d/Aura/Aura_Neumotron/.venv/Scripts:$PATH"; python -m pytest -q -p no:cacheprovider --ignore=tests/test_runtime_optimizations.py --ignore=tests/test_xtts_backend.py`. Frontend: `npm test`; browser `AURA_E2E_MOCK_ONLY=1 npx playwright test <spec>`; rebuild with `npm run build` before committing frontend.

## Review Focus

1. A rule referencing an output driven by a sensor that faults must reach a safe state (pump off; fan on) in both C++ and TS — pinned by the shared truth table (Task 3/5).
2. Re-planning the fan demo must keep GPIO4/GPIO16 exactly (Task 1).
3. A project with an unsupported part (e.g. BME280) still gets firmware for the supported parts and lists the rest as `No driver yet` (Task 3).
4. Rules referencing an IO id that no longer exists after an edit (part removed) must not crash firmware GET — they are dropped with a visible warning (Task 4).
5. Breadboard must not be added when requirements mention PCB or enclosure (Task 8).

### Task 2: IO model and rule-list validation

**Files:** Create `src/aura/firmware/io.py`, `tests/test_firmware_io.py`.

**Interfaces — Produces:**
- `DRIVERS: dict[str, Driver]` keyed by definition id per spec table; `Driver(role:"input"|"output", value:"celsius"|"percent"|"bool"|"angle", pin:"digital"|"analog"|"onewire"|"pwm", libraries:tuple[str,...])`.
- `@dataclass IoPoint(id:str, component_id:str, name:str, definition_id:str|None, role:str|None, value:str|None, unit:str, low:float, high:float, gpio:int|None, supported:bool)`. Ids: `<slug>_<n>` where slug is `temp`, `soil`, `light`, `motion`, `button`, `relay`, `led`, `servo`, or for a `logic-mosfet-module` the family of the load it switches (`fan`, `pump`, `motor`) found via its `switched-power` connection. Ranges: celsius −55..125 (DS18B20), percent 0..100, bool 0..1, angle 0..180.
- `io_points(graph) -> list[IoPoint]` — every component wired to the controller `gpio_map`; unsupported parts get `supported=False`.
- `RULES_SCHEMA` (JSON schema of the spec rule list); `class RuleError(ValueError)` with `.code`; `validate_rules(payload:dict, ios:list[IoPoint]) -> list[dict]` — codes `UNKNOWN_IO`, `WRONG_DIRECTION` (input used as output or vice versa), `OUT_OF_RANGE`, `BAD_CONDITION` (`above/below` need a numeric threshold on a numeric input; `on/off` only on bool inputs); `release` must be on the off side of `threshold`.
- `default_rules(ios) -> list[dict]` — per output, first supported input: celsius `above 26 release 24`; percent soil `below 30 release 45 minOnSeconds 5`; percent light `below 30 release 40`; bool `on`. Outputs with no input get none.

- [ ] Step 1 failing tests (`test_firmware_io.py`): plant graph ios == `[soil_1 input percent ADC1 gpio, pump_1 output bool]`; fan demo ios include `temp_1` and `fan_1`; BME280 added via library → listed `supported=False`; each RuleError code; default rules for plant equal `[{"input":"soil_1","when":"below","threshold":30,"release":45,"output":"pump_1","onValue":True,"offValue":False,"minOnSeconds":5}]`.
- [ ] Step 2–4 FAIL → implement → PASS. Step 5 commit `IO model and deterministic rule validation`.

### Task 3: Generic sketch generator + shared truth table

**Files:** Create `src/aura/firmware/generic.py`, `tests/fixtures/rule_truth_table.json`, `tests/test_generic_sketch.py`. Modify `src/aura/firmware/sketch.py` (`FirmwareArtifact`: `t_on_c`/`t_off_c` become `float|None = None`, add `kind:str="fan"`, `ios:tuple=()`, `rules:tuple=()`).

**Interfaces — Produces:** `generate_generic_sketch(graph, rules:list[dict]) -> FirmwareArtifact` (`kind="generic"`, libraries = union of used drivers, `pins={io.id: gpio}`); raises `FirmwareUnsupported` when no ESP32 DevKit controller or no supported IO. Sketch layout: header comment (revision, "generated by AURA"), `#define` per IO pin, driver setup/read/write per IO, `struct State` holding each output and its on-timestamps, `void control(unsigned long now)` generated from rules with the spec semantics (fault forces `offValue`, except outputs with slug `fan` which go on), `loop()` read → control → write, telemetry JSON once per second (`{"rev":..., "<io>":value,...}`, faulted inputs as `null`). Analog percent: `map(raw, SOIL_DRY_RAW, SOIL_WET_RAW, 0, 100)` with constants commented `// uncalibrated`.

Truth table JSON: list of cases `{rules, steps:[{t, inputs:{id:value|null}, expect:{id:value}}]}` covering above/below with hysteresis hold, on/off, minOnSeconds, later-rule-wins, fault → off, fault → fan on.

- [ ] Step 1 failing tests: generated plant sketch contains `#define SOIL_1_PIN 32` (or allocated ADC1 pin), `analogRead(SOIL_1_PIN)`, `// uncalibrated`, telemetry line; BME280 not in code and reported as unsupported; `control()` C++ body for each truth-table case compiled and executed with `g++` against the table (skip if `g++` absent); real `arduino-cli compile` of the plant sketch when `AURA_ARDUINO_CLI` exists (skip otherwise); fan demo `generate_fan_sketch` unchanged.
- [ ] Step 2–4 FAIL → implement → PASS (+ full Python suite). Step 5 commit `Generic sketch generator from drivers and rule list`.
